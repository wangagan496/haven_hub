# 腾讯云短信登录接入

2026-10-29：用户已选腾讯云短信，首期一个真实小区。代码提供真实发送路径，但本轮只使用虚构凭据和模拟腾讯云响应做自动验收，没有读取真实密钥、调用腾讯云发短信、扣费或部署生产；本地通过不代表签名/模板审核、账户权限、余额和手机收信已经验收。

## 接入资料

在腾讯云短信控制台准备已开通应用的 SmsSdkAppId、已审核通过的国内短信签名内容、验证码模板 ID 和对应地域。这里的签名配置填实际签名文字，不填签名 ID；只支持单个中国大陆手机号，服务端转换成 +86 格式。

模板变量必须和审核结果匹配：只有验证码变量时选 `TENCENT_SMS_TEMPLATE_PARAMS=code`；按顺序含验证码、有效分钟数时选 `code,minutes`，发送值是六位随机验证码和字符串 `5`。不支持任意自定义变量、营销模板或国际号码；不匹配时服务商会拒绝，不能据本地参数校验断定云端已配置正确。

由部署负责人在仓库外创建受限权限 JSON 文件，字段为 `secretId`、`secretKey`，使用临时凭据时再提供 `token`。仅授予运行服务的系统账号和必要管理员读取权限；使用最小短信发送权限的身份，禁止根账号密钥、客户端内置密钥、命令行明文密钥、将密钥发到聊天或提交 Git。代码启动时读取并校验结构，报错不回显文件内容；实际 Windows ACL、云权限及密钥轮换需要在部署环境核实，不由应用自动配置。凭据加载后驻留进程内存，轮换需安全重启，临时凭据到期不会自动刷新。

参考 `server/.env.production.example`，把非秘密业务参数和密钥文件绝对路径注入服务环境；若使用 `.env`，使用 Git 已忽略的 `server/.env`，不要创建未忽略的真实 `.env.production` 并提交。模板的必填空项故意不能启动。生产要求腾讯短信模式、HTTPS 公开来源、显式 CORS 来源（同源可空）、独立数据库绝对路径、物业电话和最低客户端版本；继续只监听本机，由同机反向代理终止 HTTPS。

开发默认仍是 `AUTH_MODE=development`，不需要任何云凭据且不发短信；即使 `NODE_ENV` 不是 production，只要设置 `AUTH_MODE=tencent` 就会真实发送并可能收费，不存在自动回退开发码。

## 登录行为与额度

`GET /code?mobile=...` 仍复用原客户端接口；真实短信成功仅返回 `development:false, expiresIn:300`，不返回验证码。Flutter 显示查收短信并开始60秒倒计时；开发模式才填入明确标记为开发的验证码。手机号在请求期间变化、页面销毁和错误响应均不误回填。

服务端在同一 SQLite 写事务预留发送资格、冷却时间和预算，再在事务外请求腾讯云。成功后仅激活仍匹配的验证码；待发送、发送失败、超时、被新请求替换或账号停用后的验证码不可登录。10秒超时覆盖请求及响应体，禁止重定向，无自动重试；响应最多64KiB。HTTP200不等于成功，必须无 Error、只有目标手机号的一条 SendStatusSet、Code为Ok且带SerialNo。Ok只表示腾讯云受理，不能保证手机已送达。

验证码有效5分钟、最多输错5次。校验、错误计数或消费及会话创建在同一写事务中，错误计数先提交再抛业务错误；多个独立进程使用同一码只允许一次成功。访问凭证30分钟、刷新凭证7天，刷新轮换和停用校验保留。验证码和会话按登录模式隔离，开发凭证不能用于腾讯短信模式。

短信同号60秒冷却，成功登录也不能清掉这一冷却；默认同号滚动1小时5次、24小时10次，可下调。`SMS_GLOBAL_DAILY_LIMIT` 没有默认值，部署负责人须按可承担费用填写滚动24小时发送上限。所有预留尝试（包括失败、超时、进程中断）均占额度，重启不清零；全局额度仅在共用这一个数据库的服务间有效，其他应用、数据库或云账号的发送不包含在内。每日限额不是自然日零点重置。旧发送记录在后续允许发送时清理，手机以哈希存于预算表，哈希不等于匿名化。

接口的每IP每分钟30次登录相关请求限制继续保留；当前未开启信任代理地址，经过同机代理时所有用户可能共用此额度，上线前须按实际代理拓扑验收并按需要配置可信代理与边缘限流，不能盲目信任任意 X-Forwarded-For。全局预算能限制本服务的最大发送尝试，不防止恶意耗尽预算；公开试点前仍需云端短信频控、费用告警及实际反滥用验收，验证码/挑战机制按风险补齐。

失败接口只返回固定提示，应用日志只记固定失败分类；不记录手机号、验证码、云端原始错误、Authorization、SecretId或SecretKey。由于既有 GET 接口在查询参数中带手机号，反向代理访问日志必须省略或脱敏查询参数，不能直接采集完整请求 URL。

## 数据与部署隔离

schema13 增加验证码/会话的 authMode、短信预算及数据库环境标识。历史会话标记为 development。首次启动生产须使用空的新数据库；已标记开发/测试的库或未标记但已有用户的旧库被拒绝，生产库也拒绝被开发服务打开，避免演示管理员权限和手机号污染正式环境。禁止混跑旧版、新版与开发模式进程；这不是针对持有数据库写权限运维人员的访问控制，也不替代真实小区数据归属方案。

环境绑定在Store完成版本迁移后校验，因此误指向旧库即使最终被环境校验拒绝，也可能已经升级schema；不要拿现用数据库试配置，升级或试读旧库前先备份，配置演练始终使用新建隔离目录。

先在受控环境首次启动空生产库，再由有权限的运维人员按现有角色管理流程开通经过核实的物业账号；本次没有开通任何真实账号，物业授权与运维审计仍需独立验收。升级前按备份手册备份并验证隔离恢复，旧程序拒绝13，不能仅替换旧可执行文件来回退新库。备份包含环境标识、预算和旧会话；恢复时仍保留生产标识，但恢复到较旧快照会回退发送计数与会话状态，需要云端额度防护并核实凭证撤销，不能把数据库备份当成完整凭证撤销机制。

本次不会自动开启公网、HTTPS、云账号服务或真实发送。公开试点前仍须在已授权的号码和预算下实测：首次收信并登录、错误码/五次锁定、重发和过期、短信失败、账号停用、代理配置与日志脱敏、密钥权限与轮换。记录时间、脱敏回执和运营方验收结论，不收集原始验证码和密钥。手机实际收信与后续完整生产交付仍是未完成项。
