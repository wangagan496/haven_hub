# 模拟器崩溃：应用侧权限精简与验证边界

日期：2026-09-21。本记录补充此前的 API 24 审计，不改写历史测试结果。

## 本次实际修改

- 从 `ohos/entry/src/main/module.json5` 移除 `ohos.permission.MICROPHONE`。
- 删除 base、en_US、zh_CN 三份字符串资源中已无引用的麦克风用途说明。
- 保留网络、相机、精确及大致定位权限，未改变分享插件注册或 Flutter Ability 生命周期。

依据：生产代码通过 `ImagePicker.pickImage` 选择/拍摄头像；本地图片选择插件的图片权限路径仅请求 CAMERA。生产代码没有录音或视频录制调用。`tool/platform_smoke.dart` 查询麦克风状态只是诊断，不构成生产功能的权限需求。

## 这项修改能解决什么

已验证新的 HAP 不再声明麦克风权限，覆盖安装后系统应用设置中不再显示麦克风开关，网络、位置、相机项仍存在。移除了无用敏感权限，以及这款应用上“撤销麦克风权限”的手工触发入口。

**这不是模拟器 Surface 堆错误的根因修复。** 相机/定位权限变化、进程结束及其他图形资源回收操作仍可能触发同类故障；不能以麦克风开关消失代替崩溃回归通过，也不能声称全部启动/退出场景已稳定。

最终运行检查已证实上述限制：22:33 左右，恢复并运行无麦克风权限的正常包，从系统应用设置返回时宿主 PID 6076 退出。监控日志记录退出码 3221226356（0xc0000374）。这次没有再次撤销麦克风权限。因无新的同路径转储，不能断言与此前每个故障栈完全相同；但足以确认此权限改动未修复模拟器整体闪退。保留权限精简的最小权限收益，不将其作为稳定性修复。

没有加入提前 detach/destroy 的生命周期钩子：尚无证据表明可在系统强制结束进程前可靠执行这些回调，重复调用引擎释放还可能引入新问题。

## 软件渲染的检查结论

维护方 tag `3.41.10-ohos-1.0.1` 的 `ohos_main.cpp` 中，`enable_software_rendering` 先设置 `kSoftware`，后续独立的 Impeller 分支又设置为 Vulkan 或 OpenGLES。故不能凭参数存在就认定预编译引擎确实启用了软件后端。

本次没有修改 Flutter 引擎，也没有验证软件渲染，因此不提供“加一个参数即可修复”的承诺。
