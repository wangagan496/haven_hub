日期：2026-10-09。本文记录客户端修复及收尾验证，补齐第四版之后的未知状态修正；取代第三版“500 原因仍未知、只改日志”的结论。面向 Claude 与无仓库访问权限的外部评审。

## 当前结论

服务端不在本地，也已通过真实测试账号推进客户端修复。新增的诊断请求取得了具体数据库报错；客户端补齐空附件数组后，正式入口实际创建成功。另发现并修复了列表只取第一页、取消路由拼写和取消状态映射问题。

这次定位与验证不依赖修改服务端。2026-10-08 原响应未在已检查的本地证据中保存，不能将今天的响应当作原响应副本。

## 客户端改动

| 问题 | 当前处理 |
| --- | --- |
| 冷启动未访问“我的”时身份永不到达 | 保留已验证的按需身份加载、共享 Future、晚到结果和会话守卫 |
| 草稿读取与保存失败混用 | 保留独立提示及重试，未确认状态仍跨进程保留 |
| 失败日志只记录 Dio message | 补 type、结构化状态和经过保护的响应摘要 |
| 失败 body 或 message 回显凭证 | String 叶子按常见凭证形态保护；非结构化响应体整体省略 |
| 列表默认只有 10 条 | 用 current / pageSize 和 pageTotal 读完全部页，无固定 100 条生产上限 |
| 后续页失败仍可能误判“没有记录” | 任一页失败、重复记录、未读够 total 时整次加载失败；会话变化停止跨页读取 |
| 无附件报修省略必需字段 | submitRepairApi 显式提交 attachment: []，原 ID 和日期格式保留 |
| 取消接口返回 404 | 路径由 cancel/repair/{id} 修正为实际的 cancel/repaire/{id} |
| 已取消记录仍显示待处理并允许取消 | 真实服务端返回 status = 0，现显示已取消、排除待处理筛选、关闭再次取消入口 |
| 状态缺失时误显示已取消，其他未知值猜成待处理 | 默认值和解析失败回退使用 unknownStatus = -1；未知状态显示“状态未知”，只在“全部”列表可见，不提供取消操作 |

未新增附件上传界面或新依赖。实际 HTTP 调用继续复用 requestDio，提示继续复用 PromptAction。日志保护只处理日志副本，不改变实际请求。

7. 原应用取消路径返回 404；有限 REST 候选 PUT /repair/{id} 同样 404。同课程公开示例提供了 repaire 路径线索，随后仅对新记录调用 PUT /cancel/repaire/{id}，返回 HTTP 200、业务码 10000，详情读回 status = 0。测试记录已取消，保留一条取消历史，没有批量清理已有记录。

## 已修正的文档判断

- GET 房屋 ID 为字符串只能说明响应类型，不能证明 POST 参数契约。
- 7177501402628096 未超过 JavaScript 最大安全整数，位数不构成精度证据。
- 报修不是唯一将 ID 放进 JSON 值的 POST；访客也包含 houseId，无需额外创建访客作对照。
- 通用 500 不能证明客户端无责，修改一个字段后仍失败不能排除该字段。
- 新请求只能取得新证据；服务端当次日志或可信契约也能协助归因，不能写成“只有重放才能定位”。
- 设备的旧日志构建应称“日志补全前”，不能误写为“身份修复前”。
- 既有记录查询未找到只能描述查询时的可见结果，不能证明历史上从未创建或从未被删除。

## 保留的边界

没有服务端源码、数据库配置或当次日志，因此未修改后端默认值、参数校验、异常处理或幂等实现。错误响应直接证明当次数据库报错涉及 attach；attachment: [] 的有效性由后续成功请求支持，但未直接核实服务端内部字段映射。没有承诺绝对避免重复创建；结果不确定时仍保留输入和二次确认。

没有附件的表单显式传空数组，附件上传不是本轮新增功能。日志保护覆盖常见凭证形态，不承诺识别任意没有标签的秘密；非结构化响应体省略，privateResponse 仍整体关闭日志。

草稿只有身份确认后才落盘。300ms 防抖和异步存储窗口仍存在，不能保证立即杀进程时最近输入一定保存。
